# Phase 9.13 — Widget info icons

Tap-to-explain "i" buttons next to every chart, table, and KPI card on the
Insights surfaces. Each icon opens a themed dialog with a description, an
interpretation hint, and (where applicable) the formula behind the metric.

## Why

The Insights screens render a lot of derived numbers — WPM, error rate,
log-scale histograms, SQL-bucketed line charts. Reading those numbers
right requires knowing the denominator, the range bucket size, and what
each axis really represents. The HTML overview page has been the only
place that documents any of this, and parts of it predate Phase 9.12 and
the recent error-rate fix (`569f331b`). Phase 9.13 puts that knowledge
on the screen itself, grounded in the current aggregator and DAO code.

## Decisions

| #  | Decision | Why |
|----|----------|-----|
| 1  | One icon per *logical* widget, not per visual element | The 6-cell global KPI strip gets one icon (covers all 6 cells). One popup with a 5-line formula block beats six tiny popups with one number each. |
| 2  | Copy lives in `strings_widget_info.xml`, ids per `info_<surface>_<widget>_<kind>` | Translation-friendly. Names are predictable so a translator can pattern-match. |
| 3  | Description grounded in code, not plan-doc prose | The plan explicitly demanded it. Several HTML descriptions disagreed with current code post-`569f331b` — the code wins. Where Trends and Habits fragments use *different* error-rate denominators, the copy says so explicitly (productive keystrokes vs. non-autocorrect keystrokes). |
| 4  | Formula rendered as plain monospaced text, no LaTeX | LaTeX would require a new dependency. Plain text is searchable and readable. |
| 5  | Theme-aware dialog (`getProperBackgroundColor`/`getProperPrimaryColor`/`getProperTextColor`) | Same Phase 6 / 9.12 discipline. Subheads use primary so they pop against the body text. |
| 6  | No Diagnostics icons | Diagnostics is a developer screen and it already has its own labels in tight space. Skipping kept the diff tractable; can be added later if asked. |
| 7  | Range and mood-filter icons explain the *control*, not a number | Those controls change every chart's bucketing — separate popups felt more useful than overloading the KPI popup. |
| 8  | `formatted="false"` on strings containing literal `%` | Lint's `StringFormatInvalid` triggers on bare `%`. Rather than escape with `%%` (which would break the rendered text), the affected strings opt out of `String.format`. |
