## Concept

A horizontally scrollable single-select chip row above the range selector. `All` + the six emoji (😊 😲 🤢 😢 😨 😠). Default `All` (current behaviour); chip row is `View.GONE` until the user records their first `MoodEntry`. When a non-`All` chip is checked, every chart and every KPI on the dashboard re-renders scoped to *sessions whose `session_id` has a `mood_entries` row with `mood_score = X`*.

Tapping the active emoji chip toggles back to `All` (mirrors Phase 8.2's mood-bar slot toggles). Filter state persists in `onSaveInstanceState` (per-screen-instance, **not** in `SharedPreferences` — see [orchestrator Decision #2](../Phase9_Plan.md#cross-cutting-decisions)).

## UX rules

- **Position:** above `dashboard_range_group`, below `dashboard_toolbar`. Chip row is the outermost filter — session selection precedes time-window selection.
- **Visibility:** `View.GONE` when `MoodDao.hasAnyMoodEntry()` returns false. Materialises on the next `onResume` after the user records their first mood entry.
- **Empty state:** non-`All` filter yielding zero sessions in the current range shows the existing `dashboard_empty_message` with a different string ("No sessions tagged with this mood yet"). Chip row stays visible so the user can recover to `All`.
- **Theme:** chips read `getProperPrimaryColor()` checked / `getProperBackgroundColor()` unchecked. No hardcoded hex literals.
- **Accessibility:** each chip's `contentDescription` = the matching `MoodEmoji.labelResFor(score)` string so screen readers announce "Happiness chip, checked".
- **Toggle behaviour:** tapping the highlighted emoji chip reverts to `All`. Tapping `All` while it's already highlighted is a no-op.
- **Mood widgets under non-`All`:** Mood Distribution panel and stacked-bar mood-mix chart render the *degenerate* one-row / one-colour result. Not a bug — that's the user feedback that the filter is in effect ([orchestrator Decision #13](../Phase9_Plan.md#cross-cutting-decisions)).
