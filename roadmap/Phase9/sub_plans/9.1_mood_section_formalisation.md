# Phase 9.1 — Mood Section Formalisation

**Sub-phase of:** [Phase 9 Orchestrator](../Phase9_Plan.md)
**Implementation order:** **1 of 10** (no dependencies; ships first; sets up the section-header pattern every other sub-phase reuses)
**Assigned agent:** `android-feature-implementer`
**Estimated complexity:** Smallest sub-phase (~50 LOC, 1 commit)
**Branch context:** Lands on `feat/phase9-global-insights-expansion` as commit `feat(phase9.1): formalise dashboard sections with primary-coloured headers`.

---

## Concept

The dashboard is about to grow from three chart cards to fifteen. The existing flat-list layout will not survive that without becoming illegible. Phase 9.1 is a pure layout pass: insert primary-coloured section header `MyTextView`s above the IKD chart group and the existing Phase 8.3 mood widgets so the dashboard reads as labelled sections rather than a wall of cards. Every later 9.x sub-phase reuses the same header style for its own section.

No new charts, no aggregator changes, no DAO changes. The only Kotlin work is one `applyCardThemeColors()` extension to tint the new headers via `getProperPrimaryColor()` on every `onResume`.

## Files to modify (only)

| File | Edit |
|---|---|
| `res/layout/activity_dashboard.xml` | Insert `MyTextView` (`dashboard_section_header_trends`) above the existing speed/IKD/error chart group. Insert second `MyTextView` (`dashboard_section_header_mood`) above `dashboard_mood_stacked_chart_card`. Both `bold`, `bigger_text_size`, top margin `@dimen/normal_margin`, no bottom margin. |
| `activities/DashboardActivity.kt` | `applyCardThemeColors()` already exists (Phase 8.1) — extend it to call `setTextColor(getProperPrimaryColor())` on the two new headers. | `res/values/strings.xml` | Add `dashboard_section_trends` ("Trends") and `dashboard_section_mood` ("Mood"). |

The full forbidden surface is in the [orchestrator §Frozen Surfaces](../Phase9_Plan.md#frozen-surfaces). For 9.1 specifically: no aggregator file, no DAO file, no chart wrapper, no new dimens, no new colours.

## Acceptance Criteria

- [ ] `./gradlew assembleCoreDebug` and `./gradlew detekt` clean.
- [ ] Two new section headers render in the dashboard above the chart groups they label.
- [ ] Headers are tinted with `getProperPrimaryColor()` on every `onResume` — verified by switching themes (light → dark) and confirming the colour updates.
- [ ] Mood section header is `View.GONE` when no mood data exists in the selected range (no orphan label above hidden cards).
- [ ] No existing chart card is moved or deleted; only headers are inserted as siblings.
- [ ] Diff is < 60 LOC across the three files.

## Notes for later sub-phases

Subsequent sub-phases (9.3 Habits, 9.5 Daily Activity, 9.7 Keystroke Dynamics) each insert their own header following this exact pattern. The string keys all begin `dashboard_section_*`; the visibility-gating idiom ("hide header when all child cards are gone") lives on a single helper in `DashboardActivity` so each sub-phase only adds one header + one tint call + one visibility predicate.
