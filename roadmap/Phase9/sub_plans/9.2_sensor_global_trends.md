## Concept

Mirror Phase 5's per-session sensor charts at the aggregate level. Two new `IkdLineChartView` cards inside the **Trends** section: **Average Gyro Magnitude over Time** and **Average Accel Magnitude over Time**. Bucketed by the existing `IkdAggregator.Range.bucketFormat` so the X axis aligns with the existing IKD/WPM/Error charts.

**Magnitude derivation** matches Phase 5: `AVG(x*x + y*y + z*z)` in SQL (SQLite has no `sqrt`), `Math.sqrt` per row in Kotlin. Null buckets render as line breaks (Phase 3 convention).

## SQL

```sql
SELECT
    strftime(:bucketFormat, timestamp / 1000, 'unixepoch', 'localtime') AS bucket,
    sensor_type AS sensorType,
    AVG(x*x + y*y + z*z) AS avgSquaredMagnitude,
    COUNT(*) AS sampleCount
FROM sensor_samples
WHERE timestamp >= :fromMs
  AND timestamp <  :toMs
  AND (:moodScore IS NULL
       OR session_id IN (SELECT session_id FROM mood_entries WHERE mood_score = :moodScore))
GROUP BY bucket, sensor_type
ORDER BY sensor_type, bucket
```

Worst case: 30 buckets × 2 sensor types = 60 rows for Month range; 14 × 2 = 28 rows for All Time. The `IS NULL` parameter form is acceptable here — see [orchestrator Decision #14](../Phase9_Plan.md#cross-cutting-decisions).

`buildSnapshot` partitions the rows by `sensorType`, takes `Math.sqrt(avgSquaredMagnitude)` per row, and merges into one `Bucket` per bucket key with both gyro and accel magnitudes alongside.
