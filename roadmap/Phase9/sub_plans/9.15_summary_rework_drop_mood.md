# Phase 9.15 — Summary Tab Rework + Drop Mood Tab

**Status:** Implemented (2026-05-10)
**Depends on:** Phase 9.14 (Summary tab landed at index 0; TabLayout w/ icons; filter bottom sheet)
**Branch:** Lands directly on `main` (user override — same pattern as Phase 9.x).
**Scope (one sentence):** The Summary tab becomes the home of the dashboard's anchor widgets — a flatter 3×2 KPI grid, the **Usage Map** (moved here, larger), and the **Mood Mix + Mood Distribution** widgets — and the dedicated **Mood tab is deleted**.

---

## 1. Why this change

Phase 9.14 introduced the Summary tab as the new landing page, but with placeholder sparklines + delta lines per the deferred-9.14.4 stub. Real-world usage shows those tile decorations weren't carrying their weight: the user is reading **the value**, not the chrome around it. Meanwhile, the Mood tab was the lowest-traffic of the six (mood entries are sparse by design); promoting its two widgets onto Summary preserves them while reclaiming a tab slot. The Usage Map was getting lost as the fifth card on the Daily Activity tab — moving it to Summary at a larger default height makes the at-a-glance "when do I type?" answer the first chart on the screen.

Net effect: every chrome row *and* every "this widget needs to be promoted" decision converges on the Summary tab as the single landing surface; Daily Activity narrows to its calendar/keypress-bar/24h/circadian cluster; the Mood tab disappears and the tab count drops 6 → 5 (so 360 dp / 5 = **72 dp per tab**, comfortable at default font).

## 2. Scope summary

### Modified
- `SummaryFragment.kt` + `fragment_dashboard_summary.xml`: KPI grid flips to **3 columns × 2 rows**; sparkline strips and delta lines removed; **Usage Map** + **Mood Mix** + **Mood Distribution** rendered below the grid.
- `item_summary_kpi_tile.xml`: drops sparkline strip and delta `MyTextView`.
- `DailyActivityFragment.kt` + `fragment_dashboard_daily_activity.xml`: **Usage Map block deleted** (card view, info icon binding, `bindUsageMap()` body, `dayHourCells` checks). The four other widgets (calendar heatmap, daily keypress bar, 24-hour bar, circadian heatmap) stay where they are.
- `DashboardPagerAdapter.kt`: tab count 6 → 5; `TAB_MOOD` removed; downstream constants renumbered (`TAB_TRENDS=1, TAB_DAILY_ACTIVITY=2, TAB_KEYSTROKE_DYNAMICS=3, TAB_HABITS=4`).
- `DashboardActivity.tabIconResFor` / `tabLabelResFor`: branches for `TAB_MOOD` removed.

### Deleted
- `MoodFragment.kt`
- `fragment_dashboard_mood.xml`
- `ic_dashboard_mood_vector.xml` (no remaining references after the activity branch is gone)
- `dashboard_tab_label_mood` string (clean removal — keeping a deprecated string in `strings.xml` would attract lint noise without buying anything)

### Untouched (still frozen)
- All aggregators (`IkdAggregator`, `IkdActivityAggregator`, `IkdMoodAggregator`, `IkdHabitsAggregator`, …) — Summary becomes a new consumer of the existing payload fields.
- DAO layer, `@Entity` classes, `IkdDatabase`, `IkdCsvWriter`, capture path.
- `WidgetInfo` / `WidgetInfoDialog` / `strings_widget_info.xml` — info icons inside the moved widgets keep working at the new render sites.
- `TrendsFragment`, `KeystrokeDynamicsFragment`, `HabitsFragment` — untouched.
- Filter bottom-sheet plumbing (`InsightsFiltersBottomSheet`) — unchanged.

## 3. Decisions

| # | Topic | Decision | Reason |
|---|---|---|---|
| 1 | KPI grid orientation | **3×2** (3 columns × 2 rows), all six tiles on screen at once | Without sparklines/deltas the tile is essentially label + value — three short tiles per row read at a glance and saves two rows of vertical space, lifting the Usage Map above the fold. |
| 2 | Sparklines + deltas | **Dropped permanently.** Retires the Phase 9.14.4 deferral. | User feedback explicit: "the current tiles don't need more details, so remove the lines". A sparkline that's actually useful would need its own tab anyway (Trends already exists). |
| 3 | Usage Map placement | **Moved entirely** to Summary; deleted from `DailyActivityFragment`. | Single source of truth; preserves the "Daily Activity = same-day-of-week patterns" framing without a duplicate widget. |
| 4 | Usage Map height | **240 dp** via inline `android:layout_height="240dp"` (no new dimen — keeps the diff small and the override discoverable inline) | The user asked for "bigger than currently by default"; the previous Daily Activity card sized via `wrap_content` settled around 160 dp on a 360 dp viewport. 240 dp is a 50 % increase and still leaves room above the fold for the KPI grid. |
| 5 | Mood widgets placement | **Moved entirely** to Summary; the dedicated Mood tab is deleted. | Mood entries are sparse by design (one per session, only when the user taps); a whole tab for two widgets that often have nothing to render was over-provisioned. Promoting them to Summary surfaces the data when present and cleanly hides when absent (gone-until-tagged rule preserved). |
| 6 | Why drop the tab vs merge into Activity | **Drop it.** Activity is "when did I type?", Mood is "how did I feel?" — different axes. Merging would dilute Activity; promoting to Summary preserves the at-a-glance landing-page semantics. | |
| 7 | Tab count after drop | **5 tabs** (Summary · Trends · Activity · Keystrokes · Habits). 360 dp / 5 = 72 dp per tab. | Plenty of width — no horizontal scroll under any default font setting. Phase 9.14.2's `MODE_FIXED` + `tabMinWidth=0` setup needs no edits beyond the drawable/label removal. |
| 8 | Mood widget reuse | **Inline the rendering** in `SummaryFragment` rather than introducing a shared "MoodWidgets" composable. | Two-call-site rule: only Summary now renders these. Adding an indirection would be premature. The `bindStackedChart` + `bindMoodLegend` + `renderMoodDistribution` methods are copied verbatim from `MoodFragment` (which is deleted). |
| 9 | Mood tab string | **Removed**, not left as a deprecated comment. | `lintCoreDebug` flags `UnusedResources`; comments in `strings.xml` invite drift. If a future tab wants the label, it can re-add it. |
| 10 | Branch hygiene | **Land on `main` directly**, single feat commit. | Same user override as Phase 9.x. The four sub-changes share the same files (Summary fragment + activity tab wiring + adapter + Daily Activity), so a single commit reads naturally. |

## 4. Acceptance criteria

The phase is done when **all** of these are green on `main`:

- [ ] `./gradlew assembleCoreDebug` BUILD SUCCESSFUL.
- [ ] `./gradlew testCoreDebugUnitTest` — existing fixtures pass (no aggregator changes).
- [ ] `./gradlew lintCoreDebug` — no new errors.
- [ ] `./gradlew detekt` — drift ≤ +5 weighted issues vs. Phase 9.14 baseline.
- [ ] Insights opens with **Summary tab selected**; **5 tabs** visible (Summary · Trends · Activity · Keystrokes · Habits) with no horizontal scroll.
- [ ] Summary tab renders a **3×2 KPI grid** (Sessions · Typing time · WPM | Error rate · Avg session · Streak) with no sparkline strip and no delta line per tile.
- [ ] KPI tile click routing unchanged from 9.14.1: Sessions / Typing time / Avg session / Streak → Habits; WPM / Error rate → Trends.
- [ ] **Usage Map** renders below the KPI grid at ≥ 240 dp height; bubble tap shows the toast (day · hour · count).
- [ ] **Mood Mix** stacked-bar chart + **Mood Distribution** panel render below the Usage Map when `moodSnap.total > 0`; both `View.GONE` when zero.
- [ ] Daily Activity tab no longer contains the Usage Map card; the four remaining widgets render unchanged.
- [ ] Mood tab is gone from the TabLayout entirely.
- [ ] Filter chip + bottom sheet behaviour unchanged from 9.14.3.
- [ ] All five Phase 9.13 widget-info icons inside the moved widgets still open the dialog (Usage Map, Mood Mix, Mood Distribution).

- No aggregator changes. The Summary tab consumes existing `payload.activity.dayHourCells`, `payload.mood`, `payload.moodMix` fields that the activity already populates on its single `Dispatchers.IO` hop.
- No filter changes. The `currentRange` / `currentMoodFilter` plumbing through the bottom sheet is unchanged.
- No widget-info dialog edits. The five info-icon `WidgetInfo` records are unchanged — they're re-attached at the new render sites in `SummaryFragment`.
- No new prefs. Filter persistence stays per-instance.
- No layout changes to the four remaining Daily Activity widgets, Trends, Keystrokes, or Habits.
- No tab-bar style changes (TabLayout config from 9.14.2 carries over verbatim).

Anything beyond this scope earns its own focused mini-plan in `roadmap/Phase9/sub_plans/`.
