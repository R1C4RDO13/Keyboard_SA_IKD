## Concept

A time-vs-date bubble chart. Y axis = calendar date (newest at top, oldest at bottom; ≈ 30 rows for Month, ≈ 90 rows for All Time at default retention), X axis = hour of day (0–23 in 1-hour columns), bubble area = keystroke count for that `(date, hour)` slot. Tappable; tooltip shows date / hour / count / locale.

Lives at the **bottom of the Daily Activity section** (introduced in 9.5) — see [orchestrator Decision #17](../Phase9_Plan.md#cross-cutting-decisions). Order in the section: calendar heatmap → daily keypress bar → hourly bar → hour×weekday heatmap → bubble Usage Map.

## Bubble UI spec

- **Min radius:** `bubble_map_min_radius_dp` (1 dp). Visible scaffold for low-activity slots.
- **Max radius:** `bubble_map_max_radius_dp` (12 dp).
- **Colour:** `getProperPrimaryColor()` at fixed alpha (size encodes count). Optional colour-by-locale variant — see [orchestrator Decision #23](../Phase9_Plan.md#cross-cutting-decisions): when more than one locale exists in the range, bubbles are coloured per locale (each locale gets its own hue in HSV; saturation and value held constant). Final visual call at implementation time.
- **Tap-target:** minimum 24 dp regardless of bubble radius (accessibility — tiny bubbles are otherwise unhittable). The hit-test inflates each bubble's pickable area to `max(radius, 12dp)` from centre.
- **Empty cells:** no bubble drawn. Y-axis row labels still present so the date scaffold is readable.
- **Y axis:** date labels every ~5 rows depending on density. Newest date at top, oldest at bottom.
- **X axis:** hour labels every 6 hours (`00`, `06`, `12`, `18`).

### Tooltip

On tap, surface a short `Toast` (or transient `Snackbar`) with the date, hour, count, and the locale recorded for the session that hour. No drilldown screen ([orchestrator Decision #24](../Phase9_Plan.md#cross-cutting-decisions)).

If the user has typed in multiple locales in the same hour-on-the-same-day (rare), show "mixed" or just the first locale found — implementation choice. Document in code comment.

## Empty state

When `activity.dayHourCells` is empty, the card is `View.GONE`. The Daily Activity section header is `View.GONE` only when all five of its cards (calendar heatmap + daily bar + hourly bar + 24×7 heatmap + this Usage Map) are hidden.
