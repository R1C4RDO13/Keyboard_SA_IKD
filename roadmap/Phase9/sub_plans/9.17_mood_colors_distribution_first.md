# Phase 9.17 — Mood color refresh + Distribution-first Summary + mood-tinted Usage Map

**Status:** Approved — ready for implementation. Preview at `insights_phase9_17_preview.html`.
**Depends on:** Phase 9.15 (Summary tab hosts the mood widgets), 9.16 (bucket-size hint, sessions-history shortcut, streak fix)
**Branch:** land directly on `main` (user override).
**Scope (one sentence):** Move the Mood Distribution panel to the very top of the Summary tab, render it as six colored emoji *tiles* with percentages instead of a bar list, double those tiles as the global color legend, refresh the six `mood_color_*` tokens to colors that match each Ekman emotion, and tint each Usage Map bubble by the dominant mood of the sessions inside its hour cell.

---

## 1. Why this change

The current Summary tab shows mood last (after KPIs and Usage Map), uses absolute counts (`12`, `8`, `4`) instead of percentages, and the six mood colors don't match the conventional emotional associations (Happiness is rendered green, which collides with Disgust). The Usage Map bubbles also have no mood awareness — they're a single neutral colour regardless of how the user felt during those sessions.

Phase 9.17 fixes all four:

1. **Distribution comes first.** Putting the colored tiles at the top of the Summary tab also gives every other widget on the screen a visible legend — the user knows what each color means before scrolling into Mood Mix or Usage Map.
2. **Percentages over counts.** Fits the 6-tile horizontal layout cleanly and makes "how is my emotional balance" readable at a glance.
3. **New mood color palette.** Match the conventional cultural associations (yellow = happy, orange = surprise, green = disgust, blue = sad, purple = fear, red = anger). One source of truth for both light and dark themes.
4. **Mood-tinted Usage Map.** Each bubble adopts the color of the dominant mood from sessions in that (day, hour) cell. Cells with no mood entries fall back to the existing primary-tinted bubble (or grey), so the chart still reads when the user hasn't tagged anything.

## 3. Summary tab restructure

New top-down order on the Summary tab:

1. **Mood Distribution tiles** (NEW position) — horizontal row of 6 cards. Each card: filled background in the mood's color, emoji at top, percentage as the big number, label below. **Absolute count is not rendered on the tile** (per-user request — keeps the tile clean and lets the percentage carry the headline). The count is still surfaced via the tap-toast: `"<emoji> <label> · 12 sessions (32%)"`. Card height ~76 dp; row scrolls horizontally if it overflows narrow widths.
2. **KPI grid** — unchanged 3×2 layout from Phase 9.15 (Sessions · Typing time · WPM · Errors · Avg session · Streak).
3. **Usage Map** — unchanged 240 dp height; bubbles re-tinted (Section 4 below).
4. **Mood Mix over Time** — unchanged stacked-bar widget; visually re-skinned for free by the new `mood_color_*` token values.

Mood Distribution tiles double as the global color legend for the screen — the user sees the color↔mood mapping before any chart that uses those colors. This removes the need for a separate `IkdStackedBarChartView` legend below the Mood Mix; we'll render the mix without a legend now (the tiles upstairs cover it).

When `mood.total == 0` (the user has never tagged a mood), all three mood widgets stay `View.GONE` — same gating rule as today.

## 4. Usage Map bubble tinting

Each `(day, hour)` bubble currently uses a single accent color. After 9.17 each bubble adopts the **dominant mood** of the sessions whose events fall in that cell.

### Aggregation

Two approaches:

- **(A) Kotlin post-processing.** Run the existing `dayHour` query unchanged; add a second small query `MoodDao.getSessionMoodMap()` that returns `Map<sessionId, moodScore>`. In the activity aggregator, for each event row remember its session_id, look up its mood, group cells by `(day, hour)`, and pick the most-frequent mood per cell. ~10 LOC of grouping; no SQL change.
- **(B) SQL JOIN.** Modify `getDayHourActivity` to `LEFT JOIN mood_entries m ON m.session_id = e.session_id` and emit one row per `(day, hour, sessionMood)`. In Kotlin, group by `(day, hour)` and pick the row with the largest count.

I recommend (A): the activity aggregator already builds the `dayHourCells` list in Kotlin, the additional query is a single small DAO call (we already have `MoodDao`), and the join is straightforward. (B) keeps the work in SQL but mutates the existing aggregator output shape in a way that ripples into other callers.

### Cell payload shape

Existing:
```kotlin
data class DayHourCell(val day: String, val hour: Int, val keystrokeCount: Int)
```
New:
```kotlin
data class DayHourCell(
    val day: String,
    val hour: Int,
    val keystrokeCount: Int,
    /** Mood score (1..6) of the most-frequent mood in this cell; null if no
     *  session in this cell has a mood entry. */
    val dominantMood: Int? = null,
)
```

`IkdBubbleMapView.setData(cells)` reads the new field and resolves the bubble color via `MoodEmoji.colorResFor(score)` (a new helper) → falls back to the current primary tone when `dominantMood == null`.

### Tooltip

Bubble tap toast extends from `"<day> HH:00 — N keystrokes"` to `"<day> HH:00 — N keystrokes · <emoji> <label>"` when a dominant mood exists. Falls back to the bare keystroke version otherwise.

## 8. Decisions

| # | Topic | Decision |
|---|---|---|
| 1 | Color palette | Match conventional emotion-color mappings: yellow happiness, orange surprise, green disgust, blue sadness, purple fear, red anger. Replaces the previous green-happiness / teal-surprise / olive-disgust which fought their conventional associations. |
| 2 | Tile layout | Horizontal 6-tile row with `MaterialCardView` per tile, full-color background, emoji + percentage + label + count stacked. Scrolls horizontally on narrow widths via `HorizontalScrollView`. |
| 3 | Counts vs percentages | Tiles show **percentage** as the only number on the tile. The absolute count is *not* rendered on the tile — it's still accessible via the tap-toast. Per the user's "remove the number on the bottom of the mood tile" call after seeing the preview. |
| 4 | Tile click target | Tiles are tappable → `Toast` shows the verbose breakdown. Future polish: long-press could open a per-mood drilldown. |
| 5 | Legend | The 6 tiles **are** the legend. No separate `IkdStackedBarChartView` legend below the Mood Mix. |
| 6 | Aggregation for dominant mood | Kotlin post-processing using a small `getAllSessionMoods()` lookup. Avoids invasive `LEFT JOIN` on the existing `getDayHourActivity` SQL. |
| 7 | Bubble color when no mood | Fall back to the existing primary-tinted neutral bubble — preserves existing visual language for "no mood data". |
| 8 | Re-tinted Mood Mix | Free side-effect of the token swap. No code change. |
| 9 | Distribution position | **First** on the Summary tab. Above the KPIs, above the Usage Map. Supports the user's "color legend at the top" requirement directly. |

## 9. Explicitly deferred

- **Per-mood click drilldown** from a tile — opens a session list filtered by that mood. Phase 9.18 candidate.
- **Mood color customization** by the user. The new palette is fixed.
- **Mood-tinting on the daily-keypress bar / 24-hour bar / circadian heatmap** in the Activity tab. Phase 9.17 only does the Usage Map; the bar charts on Activity stay primary-tinted.
- **Bubble color blending for ties.** When two moods tie for "most frequent" in a cell, pick the one with the lower (better-valenced) score. No 50/50 blend.
- **Onboarding tooltip** explaining the color↔mood legend on first run. Add later if telemetry shows users miss it.
