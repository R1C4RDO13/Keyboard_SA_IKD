## Concept

Three histograms surfacing the *distribution shape* of inter-key delay (IKD), hold-time, and flight-time over the selected range. Today the dashboard shows averages over time; BiAffect-style research dashboards lean on the distribution because log-normal tails are the actual signal — average compresses information that the histogram preserves.

New **Keystroke Dynamics** section between **Mood** and **Habits**. Each histogram has a log-scale X axis (`10–20 ms`, `20–40 ms`, …, `5120–10240 ms`) and counts on Y.

## Bucket edges

Hardcoded log-scale `LongArray` constant on the aggregator's companion object — see [orchestrator Decision #20](../Phase9_Plan.md#cross-cutting-decisions):

```kotlin
internal val BUCKET_EDGES_MS = longArrayOf(10, 20, 40, 80, 160, 320, 640, 1280, 2560, 5120, 10240)
// 10 buckets — bucketIndex 0 covers [10, 20), index 9 covers [5120, 10240).
// Events ≥ 10240 ms or < 10 ms land in the outlier overflow.
```

The SQL `CASE` ladder is generated in Kotlin from `BUCKET_EDGES_MS` — see SQL below. The same edges apply to all three metrics so the three histograms share an X axis label set.

---

## SQL (per-metric)

```sql
SELECT bucketIndex, COUNT(*) AS count FROM (
  SELECT
    CASE
      WHEN ikd_ms <  10    THEN -1
      WHEN ikd_ms <  20    THEN  0
      WHEN ikd_ms <  40    THEN  1
      WHEN ikd_ms <  80    THEN  2
      WHEN ikd_ms <  160   THEN  3
      WHEN ikd_ms <  320   THEN  4
      WHEN ikd_ms <  640   THEN  5
      WHEN ikd_ms <  1280  THEN  6
      WHEN ikd_ms <  2560  THEN  7
      WHEN ikd_ms <  5120  THEN  8
      WHEN ikd_ms <  10240 THEN  9
      ELSE 10  /* outlier overflow */
    END AS bucketIndex
  FROM ikd_events
  WHERE ikd_ms >= 0
    AND timestamp >= :fromMs
    AND timestamp <  :toMs
    AND (:moodScore IS NULL
         OR session_id IN (SELECT session_id FROM mood_entries WHERE mood_score = :moodScore))
)
GROUP BY bucketIndex
ORDER BY bucketIndex
```

The same query template is repeated for `hold_time_ms` and `flight_time_ms`. The aggregator runs all three on one `Dispatchers.IO` hop. `bucketIndex = 10` rows are folded into the `outlierCount` field; `bucketIndex = -1` rows (sub-10-ms — extremely fast typists or sentinels that slipped through) are ignored.

Worst case: 10 buckets per histogram × 3 histograms = 30 rows total per snapshot.

---

## Outlier UX

When the top bucket overflow is non-empty, render a small `MyTextView` overlay in the top-right corner of the chart card reading `"+ N outliers"` with `N = outlierCount`. Hidden when `outlierCount == 0`.

---

## Empty state

When an entire histogram is zero (e.g., the range has no events with that metric ≥ 0 — unusual but possible for a fresh installation), the matching chart card is `View.GONE`. The other two histograms render normally. The section header is `View.GONE` only when *all three* histograms are empty.
