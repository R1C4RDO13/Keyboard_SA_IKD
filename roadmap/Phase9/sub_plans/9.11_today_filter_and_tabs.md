# Phase 9.11 — Today range + Vertical tabs (NavigationRail + ViewPager2)

**Sub-phase of:** [Phase 9 Orchestrator](../Phase9_Plan.md)
**Implementation order:** **11 of 11** — read-side polish on top of every previous Phase 9 sub-phase.
**Assigned agent:** `android-feature-implementer`
**Estimated complexity:** Medium (~2 commits — TODAY range additive, vertical-tab refactor extracts ~1100 LoC of `DashboardActivity` into five fragments).
**Branch context:** Lands directly on `main` — no feature branch.

---

## Why

Two follow-up requests on `DashboardActivity` once Phase 9 was implemented:

1. **TODAY range** — the existing range toggle (Week / Month / All Time) was missing the most-immediate feedback window. A daily session can be more useful for "did my typing degrade after lunch?" type observations than even Week.
2. **Vertical tabs with horizontal swipe** — the dashboard had grown to five sections plus header rows, all on one long scroll. `NavigationRailView` (Material's vertical-tab component) on the left + `ViewPager2` on the right gives a tab strip + horizontal swipe, organising "everything inside the insights" without spawning new activities.

---

## Branch & Layering Discipline

- Lands on `main` directly (two commits: TODAY range + vertical-tab refactor).
- **No keyboard-layer reopen.** No edits to capture / sensors / IME / retention / `Constants.kt` / `Config.kt` / any `@Entity` / CSV writer / mood loaders.
- **No schema migration.** `IkdDatabase.version` stays at 3.
- **No new pref keys.** Tab index, range, and mood filter persist via `Bundle` only — same discipline as Phase 9 Decision #2.
- **No new dependency.** `androidx.viewpager2`, `androidx.fragment`, and `com.google.android.material:material` (which provides `NavigationRailView` since 1.4.0) are all already on the runtime classpath through `fossify-commons` 6.1.6.

## Decisions

| # | Topic | Decision |
|---|---|---|
| 1 | TODAY default? | **No.** Default stays `WEEK` per Phase 3. Today is opt-in. |
| 2 | Streak unit under TODAY | New `StreakUnit.HOURS` enum value; activity renders the streak KPI as `"Today"` / `"—"` instead of a count + suffix because the streak walks hourly buckets within a single calendar day. |
| 3 | Calendar heatmap under TODAY | **Hidden.** A 1×7 cell grid is not useful. |
| 4 | Daily keypresses bar under TODAY | **Hidden.** Single bar = degenerate. |
| 5 | Usage Map under TODAY | **Hidden.** Single date column = degenerate. |
| 6 | 24-hour bar under TODAY | **Visible.** Hourly buckets fit naturally — TODAY actually makes this chart more focused. |
| 7 | Circadian heatmap under TODAY | **Visible (unchanged).** Always all-time per Phase 9 Decision #18; range doesn't affect it. |
| 8 | Activity-quality scatter under TODAY | **Visible.** One bubble (today). Still useful as a snapshot. |
| 9 | Habits trend charts under TODAY | **Visible.** Each chart renders one X tick — minimal but non-degenerate. |
| 10 | Vertical tab component | **`NavigationRailView`** (Material's vertical-tab component) — matches the user's "vertical tabs" wording literally. Already on classpath via `com.google.android.material:material:1.13.0`. |
| 11 | Swipe behaviour | **`ViewPager2` with horizontal orientation.** The user said "swipe left or right" — that's literal. |
| 12 | Tab labels | **Lifted from existing `dashboard_section_*` strings** so the rail labels match the section names users already saw above each section. |
| 13 | Tab icons | Five new theme-neutral Material Symbols vectors (`trending_up`, `calendar_today`, `sentiment_satisfied`, `keyboard`, `local_fire_department`) tinted with `?attr/colorControlNormal`. |
| 14 | Tab index persistence | **`onSaveInstanceState` only.** Same discipline as range / mood-filter — no `SharedPreferences`, no new pref key. Default is Trends (index 0). |
| 15 | Global header on every tab | **Yes.** AppBar, mood filter chip row, range toggle, four-cell KPI strip stay above the rail+pager; they apply globally. Per-tab section headers (the Phase 9.1 primary-coloured `MyTextView`s) are gone — the NavigationRail label replaces them. |
| 16 | Per-tab empty placeholder | Each fragment owns its own `fragment_*_empty_message` `MyTextView` (visible only when every card in the tab is GONE). The activity's existing `dashboard_empty_message` still drives the "no sessions at all" case. |
| 17 | Render dispatch | Activity loads → holds `latestPayload` → dispatches `renderPayload` to every attached fragment with `view != null`. Fragments pick up the latest payload on `onResume` via `renderFromHostIfReady` for the swipe-to-newly-attached case. |
| 18 | Offscreen page limit | `TAB_COUNT - 1` — keeps every fragment in memory so swipe re-renders are instant and chart caches survive page changes. |
| 19 | `setupMaterialScrollListener` | **Dropped on this activity.** The host body has no single `ScrollingView`; each fragment owns its own `NestedScrollView`. AppBar still renders correctly; only the small scroll-elevation animation is missing. |
| 20 | Detekt drift | **Zero.** New files contribute no `MagicNumber` / `LongMethod` / `LargeClass` warnings. The existing 52 weighted issues are unchanged; the rewritten `DashboardActivity` (now ~340 LoC, down from ~1100) actually reduces the surface where detekt could flag. |
