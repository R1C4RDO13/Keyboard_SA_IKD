# Phase 9.14 — Summary Tab + Tab Icons + Filter Consolidation

**Status:** Planned
**Depends on:** Phase 9.11 (vertical tabs → top tabs), 9.12 (tab styling + global KPI strip), 9.13 (info icons)
**Branch:** land directly on `main` (user override — same pattern as Phase 9.x).
**Scope (one sentence):** Replace the current four-row global header (KPI strip · tab toggle · range toggle · mood chip row) with **a single tab bar of six icon+label tabs** (the new Summary tab hosts the KPI grid that previously lived as persistent chrome) plus a single active-filter chip; range and mood filters consolidate behind a toolbar Filters icon that opens a bottom sheet.

This is the "Option A · Variant 2 · Layout A" combination from `insights_redesign_optionA_variants.html`, with the hard constraint that **all six tabs fit without horizontal scrolling** at default font size on a 360 dp screen.

## 1. Why this change

After Phase 9.12 the dashboard has five chrome rows before the first chart appears: toolbar · KPI strip (6 cells, scrolls) · tab toggle (5 buttons, scrolls) · range toggle (4 buttons) · mood chip row (gone-until-tagged but still 5th row when present). On a 360 dp viewport this consumes ~35–40% of the visible area.

The two filter rows (range, mood) are *set-once-then-ignored* by most users — but they take permanent vertical space. The KPI strip is a header *and* the most viewable summary in the app — but it scrolls, which is awkward for at-a-glance reading. And the tab toggle visually competes with the range toggle (both `MaterialButtonToggleGroup`s look identical).

Phase 9.14 collapses all that into:
- One **tab bar** with 6 icon+label tabs, fixed-width (no horizontal scroll), each tab carries a vector icon stacked over its label.
- The first tab — **Summary** — hosts the KPIs as a 2×3 grid of generous tiles with sparklines and "tap to jump" hooks into the relevant deeper tab. The grid is on the tab content, no longer in the activity chrome.
- Range and mood filters move into a **bottom sheet** behind a toolbar Filters icon. Active filter is surfaced as a single chip below the tab bar.

Net effect: chrome rows drop from 5 → 2 (toolbar + tab bar) plus an optional filter chip when filters are active. Charts come above the fold on every screen size.

## 4. Sub-phases (3)

### 9.14.1 Summary tab + KPI grid

**Goal:** A new Summary tab is the landing page; it hosts the KPI cells in a 2×3 grid. The KPI strip in the activity chrome is gone. Tabs still render via the Phase 9.12 toggle group (no icons yet) — the tab bar redesign comes in 9.14.2.

#### Deliverables
- New `SummaryFragment` + layout. Six `MaterialCardView` tiles in a 2-column, 3-row `GridLayout` (or `LinearLayout` of two `LinearLayout` rows for SDK simplicity). Each tile uses `<include layout="@layout/item_summary_kpi_tile"/>` populated with id/value/delta/icon.
- Tile content per mock (Layout A from `insights_redesign_optionA_variants.html`):
  - Header row: tiny icon + uppercase label.
  - Big value (`bigger_text_size`, bold).
  - Delta vs previous range (small green/red text). The delta is the new field — see "Sparkline / delta scope" below.
  - Sparkline placeholder (4–8 px tall coloured strip; the actual sparkline rendering is deferred to 9.14.4).
- Tile click handler: `setOnClickListener { (parentFragment as DashboardFragmentHost).goToTab(R.id.dashboard_tab_<x>) }`. Sessions / Typing time / Avg session / Streak → Habits tab. WPM / Error rate → Trends tab.
- `DashboardActivity` shifts every existing tab right by one and removes the KPI strip from `activity_dashboard.xml`. Range toggle, mood chip row, and tab toggle stay in place at the top for now (9.14.2 swaps the tab toggle; 9.14.3 swaps the filter rows).

#### Sparkline / delta scope (Phase 9.14.4 deferred)
- Real sparklines need a per-bucket data trail per KPI (small line chart inside each tile). The aggregators already produce per-bucket rows via `IkdAggregator.Snapshot.buckets` and `IkdHabitsAggregator.HabitsSnapshot.buckets`; rendering them is a new tiny custom view.
- For 9.14.1, render an empty placeholder strip and a hard-coded `—` for the delta. 9.14.4 adds the real sparkline + delta computation. Reason: keeps 9.14.1 a pure layout-and-fragment commit.

#### Acceptance
- `./gradlew assembleCoreDebug` BUILD SUCCESSFUL.
- `./gradlew testCoreDebugUnitTest` — existing fixtures pass (no aggregator changes).
- Open Insights → Summary tab is selected by default → six tiles visible with current values; tapping each tile jumps to the right parent tab.
- Tabs are still the Phase 9.12 segmented toggle (no icons yet); they now read **Summary | Trends | Activity | Mood | Keys | Habits**.

### 9.14.2 Tab bar V2 (TabLayout, icons, no scroll)

**Goal:** Tabs render as Material 3 `TabLayout` in `MODE_FIXED` with `tabMinWidth="0dp"` so all six fit at default font size without horizontal scrolling. Each tab carries a vector icon stacked over its label.

#### Deliverables
- Replace `MaterialButtonToggleGroup` (currently in `activity_dashboard.xml`) with:
  ```xml
  <com.google.android.material.tabs.TabLayout
      android:id="@+id/dashboard_tab_layout"
      android:layout_width="match_parent"
      android:layout_height="wrap_content"
      app:tabMode="fixed"
      app:tabGravity="fill"
      app:tabMinWidth="0dp"
      app:tabIndicatorAnimationMode="elastic"
      app:tabIconTint="@color/dashboard_tab_icon_tint"
      app:tabTextColor="?android:attr/textColorSecondary"
      app:tabSelectedTextColor="?attr/colorPrimary"/>
  ```
- New `res/color/dashboard_tab_icon_tint.xml` selector — `?attr/colorControlNormal` for unselected, `?attr/colorPrimary` for selected.
- Wire to `ViewPager2` via `TabLayoutMediator(tabLayout, viewPager) { tab, position -> tab.setIcon(...) ; tab.setText(...) }`. Replaces the manual two-way sync code from Phase 9.12.
- Six new vector drawables under `res/drawable/` (see [Section 5](#5-tab-icons-drawables)).
- Six new strings: `dashboard_tab_summary`, `dashboard_tab_trends`, `dashboard_tab_activity`, `dashboard_tab_mood`, `dashboard_tab_keystrokes`, `dashboard_tab_habits`. Keep labels short (≤ 9 chars at default font) so they fit in 60 dp at 360 dp viewport. Already-existing labels (e.g. `dashboard_tab_label_keystroke_dynamics` from 9.12) are renamed: "Activity", "Keys", "Habits".
- Theme integration: `applyThemeColors()` already runs `updateTextColors`; tab text picks up `?attr/colorPrimary` and `?android:attr/textColorSecondary` automatically. Tab indicator colour pulls from `?attr/colorPrimary` by default — confirm Fossify's primary token threads through.

#### Width verification
At 360 dp viewport: 360 / 6 = 60 dp per tab. Icon (24 dp) over text (10–11 sp ≈ 14 dp tall) requires ~46 dp width including margins. **All six labels at default font fit at 360 dp.** On 320 dp devices (rare), abbreviate "Activity" → "Active" or "Today" if needed via a `values-sw320dp/strings.xml`.

#### Acceptance
- `./gradlew assembleCoreDebug` BUILD SUCCESSFUL.
- All six tabs visible at once on 360 dp screen — no horizontal scroll. Verified visually on emulator.
- Active tab indicator + label use Fossify primary colour; inactive use the theme's secondary text.
- Swipe ViewPager2 → tab indicator follows. Tap a tab → pager pages.
- Active tab persisted on rotate via `onSaveInstanceState`.

#### Commit
`feat(phase9.14.2): replace tab toggle with TabLayout (icons, fixed mode, no scroll)`

### 9.14.3 Filter consolidation (Option A)

**Goal:** Range and mood filters move into a bottom sheet behind a toolbar Filters icon. The active filter is surfaced as a single chip below the tab bar (visible only when a non-default filter is active).

#### Deliverables
- New `helpers/InsightsFiltersBottomSheet.kt` extending `BottomSheetDialogFragment`. Body contains:
  - Section label "Range" + segmented `MaterialButtonToggleGroup` (Today / Week / Month / All Time).
  - Section label "Mood" + horizontal chip strip (All + 6 emoji), only shown if `MoodDao.hasAnyMoodEntry()` returns true.
  - Reset button (returns to Week + All).
  - Apply button (commits the selection back to the activity via a `setFragmentResultListener` channel or a shared `ViewModel`).
- New `res/layout/dialog_insights_filters.xml` themed via `getProperBackgroundColor` / `getProperTextColor` / `getProperPrimaryColor` (Phase 9.13 dialog discipline; same fallback for `dialog_bg` / `dialog_you_background` / `black_dialog_background`).
- New `res/menu/menu_dashboard.xml` adds a Filters action with `ic_filter_vector` icon (`showAsAction="ifRoom"`).
- New active-filter chip in `activity_dashboard.xml`, just below `dashboard_tab_layout`. Hidden when range == Week and mood filter is null. Otherwise text reads:
  - Mood-only: `"😊 Happy"` (with × dismiss).
  - Range-only: `"Today"` / `"Month"` / `"All time"`.
  - Both: `"Week · 😊 Happy"`.
- Tap the chip's body → opens the bottom sheet for further editing. Tap the × → resets that filter.
- Remove the standalone range toggle and mood chip row from `activity_dashboard.xml`.
- Remove the corresponding setup code in `DashboardActivity.kt` (the chip-row binding + range-toggle binding).
- Persist filter state via `onSaveInstanceState` — same scheme as Phase 9.4 (per-instance, not `SharedPreferences`).

#### Acceptance
- Toolbar shows the Filters icon. Tap → bottom sheet opens with current state pre-selected.
- Change range to Month, mood to 😊, tap Apply → bottom sheet closes; chip reads "Month · 😊 Happy"; every chart re-aggregates on the same `Dispatchers.IO` hop.
- Tap the chip body → sheet reopens at current selection. Tap × → both reset to defaults; chip vanishes.
- Reset button in the sheet returns to Week + All.
- No regression in the Phase 9.4 mood-filter behaviour (chips disabled until first mood entry; aggregators wired through `*ForMood` queries).
- Active tab + filter state both survive rotation.

#### Commit
`feat(phase9.14.3): collapse range + mood filters into toolbar Filters bottom sheet`

## 5. Tab icons (drawables)

Six new vector drawables in `res/drawable/`. Each is a Material symbol re-exported as a tinted vector (`?attr/colorControlNormal` so the active state can override via the tint selector). Suggested mapping:

| Tab | Drawable file | Material symbol |
|---|---|---|
| Summary | `ic_dashboard_summary_vector.xml` | `dashboard` (the 4-quadrant grid) |
| Trends | `ic_dashboard_trends_vector.xml` | `trending_up` or `show_chart` |
| Activity | `ic_dashboard_activity_vector.xml` | `calendar_month` |
| Mood | `ic_dashboard_mood_vector.xml` | `mood` (smiley) |
| Keystrokes | `ic_dashboard_keystrokes_vector.xml` | `keyboard` |
| Habits | `ic_dashboard_habits_vector.xml` | `repeat` or `auto_awesome` |

Standard 24 × 24 viewport, single-path where possible, `android:tint="?attr/colorControlNormal"` and the `tabIconTint` color selector override per-state. Keep them simple — these compress to ~150 bytes each as compiled vectors.

The Filters toolbar icon `ic_filter_vector.xml` mirrors `tune` from Material symbols.

## 8. Decisions

| # | Topic | Decision |
|---|---|---|
| 1 | Tab order | **Summary first**, then Trends · Activity · Mood · Keys · Habits. Summary is the new landing page; all other ordering preserved from Phase 9.12. |
| 2 | Tab control | **Material 3 `TabLayout`** in `MODE_FIXED` with `tabMinWidth="0dp"`. Replaces Phase 9.12's `MaterialButtonToggleGroup`. Reason: TabLayout natively supports icon-over-text in fixed mode and the equal distribution; toggle-group buttons would need per-button `weight` and a custom layout. |
| 3 | Tab style | **Variant 2 (icon stacked over text)**. Verified six labels fit at 360 dp / 60 dp per tab with default font. |
| 4 | KPI grid layout | **Layout A (2×3 with sparklines)**. Six tiles, each tappable, each carrying a delta vs the previous comparable range. |
| 5 | Sparkline rendering | **Deferred to 9.14.4**. 9.14.1 ships a placeholder strip and `—` delta to keep the commit a pure layout move. |
| 6 | Aggregator surface | **Reused as-is.** Summary tab's six KPI values come from `IkdAggregator.snapshot` (sessions, typing time, WPM, error rate) and `IkdHabitsAggregator.snapshot` (avg session, longest streak) — already on the same IO hop. No new SQL, no new aggregator. |
| 7 | KPI tile click target | **Whole tile is clickable.** Sessions / Typing time / Avg session / Streak → Habits tab. WPM / Error rate → Trends tab. Implemented via a single `goToTab(position)` method on the activity exposed to fragments. |
| 8 | Filter consolidation | **Bottom sheet + active chip.** Toolbar Filters icon opens the sheet; active filter chip below the tab bar surfaces non-default state. Tap chip body → sheet; tap × → reset that filter. |
| 9 | Bottom sheet kind | **`BottomSheetDialogFragment`** rather than `BottomSheetBehavior`. Canonical dismiss + theme tinting per Phase 9.13 dialog discipline. |
| 10 | Filter persistence | **`onSaveInstanceState` only.** Per-instance, not `SharedPreferences` — consistent with Phase 9.4. |
| 11 | Mood-section visibility | **GONE until `MoodDao.hasAnyMoodEntry()` returns true.** Same gating as Phase 9.4's chip row. |
| 12 | Tab labels | Short forms: Summary · Trends · Activity · Mood · **Keys** · Habits. "Keystroke Dynamics" was already abbreviated to "Keystrokes" in Phase 9.12; further shortened to "Keys" for the 60 dp width. |
| 13 | Sub-phase split | **Three commits.** 9.14.1 lands the Summary fragment + grid (no tab-bar change). 9.14.2 swaps in `TabLayout` + icons. 9.14.3 collapses filters into the bottom sheet. Each compiles, runs and is reviewable independently. |
| 14 | Branch hygiene | **Land on `main` directly.** Same user override as Phase 9.x. No feature branch. |
| 15 | Ordered tab IDs | Tab positions are addressed via stable constants in `DashboardActivity` (e.g. `TAB_SUMMARY = 0, TAB_TRENDS = 1, …`). Avoids brittle index arithmetic when wiring KPI tile clicks. |
| 16 | Drawable tinting | **Theme-aware** via `?attr/colorControlNormal` (unselected) + `?attr/colorPrimary` (selected) through a `res/color/dashboard_tab_icon_tint.xml` selector. Phase 6 lesson; no `Color.parseColor` literals. |

## 9. Explicitly deferred

Listed here so we don't relitigate scope mid-phase.

- **Sparklines + delta on KPI tiles.** 9.14.4 follow-up. Needs a tiny custom `View` (Path + linear interpolation through the existing `Snapshot.buckets` series) plus the previous-range delta computation (re-aggregate against `range.shift(-1)`). Out of 9.14.1 to keep that commit a pure layout move; out of 9.14.2/3 because they're already loaded.
- **Per-tile info icons.** Each Summary tile could surface its own Phase 9.13 `WidgetInfo` popup (the global KPI strip's existing one is the natural fallback for now). Polish, not a blocker.
- **Compound filters.** Multi-mood selection on the bottom sheet (e.g. show Happy + Surprise combined). Phase 9.4 deferred this; 9.14.3 doesn't reopen it.
- **Bottom-nav variant.** Option C from the redesign-proposals HTML. Larger refactor, locks tab count at 5, and would conflict with adding Summary as a 6th. Not pursued.
- **Animated tab indicator transitions.** Material 3 `tabIndicatorAnimationMode="elastic"` is set; further customisation (e.g. shared-element transition between tab and content) is out of scope.
- **Tab badging** (e.g. red dot on Mood when a new entry was just added). Not requested; can revisit if telemetry shows users miss the chip-row removal.
- **Onboarding tooltip pass** for the new Filters icon and the Summary tab. If user feedback shows the Filters icon is undiscoverable, a one-time `Snackbar` tour can be added under a tiny `Config.firstFiltersIconShown` flag.

Anything from this list earns its own focused mini-plan in `roadmap/Phase9/sub_plans/` if and when it's wanted.
