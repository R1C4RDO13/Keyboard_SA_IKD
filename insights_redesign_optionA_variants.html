Insights — Option A Variants

You picked Option A (filters behind a single icon) and asked for two refinements: move the KPI strip into its own tab, and add icons to the tabs. The dashboard now has six tabs — Summary as the new landing page hosting the KPI cards, plus the existing five. Below: three variants of how the tab bar can render those six tabs, all sharing the same Summary content. Pick any one — they're swap-in equivalents.

Icon mapping

Six tabs · the Summary lands first; the rest preserve their current order. All icons here are Material symbols (rendered as emoji in this preview for portability — swap for vector drawables in the actual app).

Trade-off

  • Maximum readability — every tab carries both an icon and a word, removing all guesswork.
  • Six tabs at default font may overflow narrow widths and need horizontal scrolling. The current Phase 9.12 implementation already wraps the toggle in a HorizontalScrollView, so this is a non-issue mechanically — but the user has to swipe to see the rightmost tabs (Habits sometimes hidden initially).
  • Closest to the existing Phase 9.12 layout — minimum surprise.
  • Touch target is the full row width per tab. Generous on a 360 dp screen.

~½ day

Trade-off

  • Most compact tab bar of the three — ≈ 44 dp tall, single line, no scroll.
  • First-time users have to either tap icons to see labels, or rely on memory. Icon discoverability is key — the Summary 📊 / Mood 😊 / Habits 🔁 mappings are not universal.

Recommendation

A pragmatic pairing.

Pair Variant 2 (icon stacked over text) with Summary Layout C (KPI grid + headline charts). Reasoning:

  • V2 over V1: all six labels visible without scrolling at default font size; the slightly taller bar costs ~20 dp but you've already reclaimed ~80 dp by moving filters to a chip — net positive.
  • V2 over V3: the Summary 📊 / Mood 😊 / Habits 🔁 mapping isn't universal, and the cost of one extra row on the tab strip is much smaller than the cost of users tapping the wrong tab. Save icon-only for a v2 polish if the bar feels too dense.
  • Layout C over A or B: the new Summary tab is the landing page; users opening Insights expect a glance answer ("how am I doing?"). KPI grid alone is a glance, but adding the WPM and error-rate mini-charts gives shape — see whether numbers are climbing or sagging without leaving the tab.
  • Each KPI tile becomes tappable → jumps to its parent tab (e.g. tap "WPM" → Trends tab). Cheap to wire (one setOnClickListener per tile that calls viewPager.setCurrentItem(...)); huge payoff in navigation flow.
Implementation hint: the Summary tab's six KPI cells reuse the values your global header already computes (IkdAggregator.snapshot + IkdHabitsAggregator.snapshot) — no new aggregator. The two headline charts reuse IkdLineChartView + IkdAggregator.Bucket outputs already produced for the Trends tab. Net new code: one fragment + layout + an updated FragmentStateAdapter that puts Summary at index 0.
