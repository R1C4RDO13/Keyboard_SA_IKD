01 · Overview & conventions

One source of truth, three audiences

All insights read from ikd.db. Capture is privacy-gated — no rows exist unless the user has flipped privacy mode off. Each dashboard scopes the data differently.

Visualisation types — colour-coded throughout this document
KPI cell Chip / metadata Line chart Bar chart Stacked bar Histogram Heatmap Donut / Pie Scatter Bubble map Input Status Navigation
🛡️

Privacy-first

No raw text stored or displayed — only event categories (ALPHA, SPACE, BACKSPACE, EMOJI, AUTOCORRECT) and timestamps.

📖

Read-side only

Every dashboard is computed from existing capture rows. Adding a new dashboard never modifies the keyboard / IME / capture layer.

∅

Empty states are first-class

Each card hides itself when its query is empty; each tab shows a placeholder when every card is empty; activity shows a global "no sessions" message at zero data.

⚡

One IO hop per refresh

Global dashboard fans every aggregator call onto a single Dispatchers.IO coroutine, then renders all fragments off the same payload.

Cross-tab aspects
  • Range awarenessEvery aggregator takes the same Range enum (Today / Week / Month / All Time). TODAY switches daily widgets to hourly buckets and hides date-keyed widgets that would degenerate.
  • Mood filter scopeFilter applies to every tab except Mood itself (a mood-filtered Distribution would be a one-row chart — the chip is the feedback that the filter is in effect).
  • Empty-state contractEach card hides when its query is empty; each tab shows a placeholder when every card is empty; the activity shows a global "no sessions" message at zero data.
  • ThemingEvery MaterialCardView calls setCardBackgroundColor(getProperBackgroundColor()) so the dashboards track Fossify's runtime theme palette in both light and dark modes.

05 · Data flow & aggregation

Where every number comes from

Twelve aggregators / loaders, all sharing one shape: suspend fun snapshot(range) on Dispatchers.IO, pure-Kotlin Companion derivation, debug-only wall-clock log.

Aggregator inventory
IkdAggregator
Global header KPI · Trends tab · Mood (bucket alignment)
Snapshot — List<Bucket> with WPM / avg IKD / error % per time bucket

SQLite strftime for daily / weekly buckets. WPM denominator excludes AUTOCORRECT.

IkdMoodAggregator
Mood tab
MoodSnapshot (counts) + MoodMixSnapshot (per-bucket per-category)

Two SQL queries, both bounded to ≤ 30 daily / ≤ 14 weekly buckets.

IkdActivityAggregator
Daily Activity tab
Daily / hourly / circadian / day-hour cells

Mixes daily, hourly and weekday × hour SQL projections for the four widgets.

IkdDistributionAggregator
Keystroke Dynamics tab (3 histograms)
Three log-scale histograms with outlier counts

Bucket boundaries computed in Kotlin; SQL streams the raw timing values within range.

IkdOrientationAggregator
Keystroke Dynamics tab (donut)
Per-orientation session count + duration

Three slices — Portrait / Landscape / Unknown. Unknown covers pre-Phase 2 sessions + sessions where orientation capture was disabled.

IkdHabitsAggregator
Habits tab (4 trend charts) · global KPI strip
HabitsSnapshot — totals + per-bucket session-level rollups + streak unit

Streak unit varies by range (HOURS / DAYS / WEEKS) so the KPI label can adapt.

IkdQualityAggregator
Habits tab (scatter)
One DayQualityPoint per day with backspace + autocorrect counts

Day index drives the alpha fade of older points.

IkdSensorTrendAggregator
Trends tab (gyro / accel)
Per-bucket avg gyro / accel magnitude

Magnitude derived in Kotlin from AVG(x*x+y*y+z*z) — SQLite has no sqrt.

IkdSessionStatsLoader
Per-session dashboard (KPI + chip row + metadata)
SessionStats — counts, averages, durations

One SQL round-trip; sentinels excluded via AVG(CASE WHEN col >= 0 …).

IkdSessionChartLoader
Per-session dashboard (3 line charts)
SessionChartData — IKD / gyro / accel series

Bucket width auto-scaled; ≤ 200 points per chart regardless of session length.

IkdMoodLoader
Per-session dashboard (mood KPI cell)
Optional MoodEntry for the session

Cell hidden when null.

LiveCaptureSessionStore
Diagnostics dashboard
In-memory event + sensor lists for the active session

Push-based — no Room reads. Drains to Room every 500 ms or 100 events.

Performance budgets

Global aggregator

  • Week < 100 ms · Month < 150 ms · All Time < 200 ms

Per-session chart loader

  • 30 s session < 100 ms · 5 min < 200 ms · 1 hour < 400 ms

Telemetry

  • Every loader logs its own wall-clock duration in debug builds — tags IkdAggregator · IkdMoodAggregator · IkdSessionStatsLoader · IkdSessionChartLoader.
Schema referenced
  • sessions — id, started_at, ended_at, counts, orientation, locale
  • ikd_events — session_id (FK CASCADE), timestamp, event_category, ikd_ms, hold_time_ms, flight_time_ms, is_correction, correction_weight
  • sensor_samples — session_id (FK CASCADE), timestamp, sensor_type (GYRO / ACCEL), x, y, z
  • mood_entries — id, session_id (FK CASCADE, unique), timestamp, mood_score (1..6)
Read-side only. Every aggregator listed here is additive over the existing capture rows. New dashboards or chart variants can be designed without reopening the keyboard / IME / capture layer.

Phase 9.11 — TODAY range + vertical tabs

Error-rate denominator fix (post-Phase 8.3)

Commit 569f331b · manual test plan roadmap/ErrorRateFix_TestPlan.md

  • Two bugs in the Phase 7.1 weighted error-rate metric. (1) Denominator only excluded AUTOCORRECT rows, so typing hello world (11 chars) and backspacing all 11 read 11/22 = 50 % instead of the user-expected 100 %. Fixed by switching the denominator to productive keystrokes — eventCount - correctionCount — which excludes both AUTOCORRECT and BACKSPACE.
  • (2) BACKSPACE rows always carried correction_weight = 1, even when one keypress deleted an N-char selection. Fixed by reading the selection length (or getCountToDelete()) before recording the timing event — new SimpleKeyboardIME.computeBackspaceWeight() helper.
  • Net: ocasdasda + autocorrect stays at 90 %; hello world<BS×11> now reads 100 %; legacy backfill drifts 18.18 % → 20 %.
