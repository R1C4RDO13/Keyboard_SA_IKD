Overview & conventions

All insights surfaces read from the same Room database (ikd.db). Capture is privacy-gated — no rows exist unless the user has flipped privacy mode off.

The app exposes three distinct insights surfaces, each with a different scope and audience:

  • Global Insights Dashboard — aggregated trends across all stored sessions. Five tabs, one shared global header (range + mood filter + KPI strip).
  • Per-Session Dashboard — single-session deep dive. Same shape as one tab of the global dashboard but bounded to one session_id.
  • Diagnostics Dashboard — live developer screen, populated by the in-memory LiveCaptureSessionStore rather than by Room queries. Used to verify capture is working.

Visualisation types in use

The legend below is also used as colour-coded tags on every widget table.

KPI cell Chip / metadata strip Line chart Bar chart Stacked bar Histogram Heatmap Donut / Pie Scatter Bubble map

Cross-cutting principles

  • Privacy-first. No raw text is ever stored or displayed — only event categories (ALPHA, SPACE, BACKSPACE, EMOJI, AUTOCORRECT, …) and timestamps.
  • Read-side only. Every dashboard is computed from existing capture rows. Adding a new dashboard never modifies the keyboard layer.
  • Empty states are first-class. Every card hides itself when the underlying query returns nothing; the parent tab shows a placeholder when all its cards are empty.
  • One IO hop per refresh. The global dashboard fans out all aggregator calls onto a single Dispatchers.IO coroutine and renders fragments off the same payload.

Cross-tab aspects

  • Range awarenessEvery aggregator takes the same Range enum (Today / Week / Month / All Time). TODAY switches daily widgets to hourly buckets and hides date-keyed widgets that would degenerate.
  • Mood filter scopeFilter applies to every tab except the Mood tab itself (a mood-filtered Mood Distribution would be a degenerate one-row chart — the visible filter chip is the feedback that the filter is in effect).
  • Empty-state contractEach card hides when its query is empty; each tab shows a placeholder string when every card is empty; the activity shows a global "no sessions" message when the database has none at all.
  • ThemingEvery MaterialCardView calls setCardBackgroundColor(getProperBackgroundColor()) on render so the dashboards track Fossify's runtime theme palette in both light and dark modes.

  • Mode switchingThe same activity hosts a live raw-event log when launched without EXTRA_SESSION_ID. The XML keeps both containers and toggles visibility in onCreate to avoid a frame of the wrong layout.
  • Empty-card handlingSessions captured with sensors disabled show "No data" inside the card silhouette rather than removing the card outright — keeps the layout stable across sessions.
  • PerformanceBucket-width formula keeps the chart wire footprint constant in session length: 10 s → 50 ms buckets / 200 pts; 1 hour → 18 s buckets / 200 pts.

4. Data flow & aggregation strategy

A summary of where each dashboard's numbers come from, since the redesign work will probably want to move some widgets between surfaces or consolidate aggregators.

Aggregator inventory

AggregatorUsed byReturnsNotes
IkdAggregator Global header KPI strip · Trends tab · Mood tab (bucket alignment) Snapshot — List<Bucket> with WPM / avg IKD / error % per time bucket SQLite strftime for daily/weekly buckets. WPM denominator excludes AUTOCORRECT.
IkdMoodAggregator Mood tab MoodSnapshot (counts) + MoodMixSnapshot (per-bucket per-category) Two SQL queries, both bounded to ≤ 30 daily / ≤ 14 weekly buckets.
IkdActivityAggregator Daily Activity tab Daily / hourly / circadian / day-hour cells Mixes daily, hourly and weekday×hour SQL projections for the four widgets.
IkdDistributionAggregator Keystroke Dynamics tab (3 histograms) Three log-scale histograms with outlier counts Bucket boundaries computed in Kotlin; SQL just streams the raw timing values within range.
IkdOrientationAggregator Keystroke Dynamics tab (donut) Per-orientation session count + duration Three slices: Portrait / Landscape / Unknown. Unknown covers sessions captured before Phase 2 + sessions where orientation capture was disabled.
IkdHabitsAggregator Habits tab (KPI + 4 trend charts) HabitsSnapshot — totals + per-bucket session-level rollups + streak unit Streak unit varies by range (HOURS / DAYS / WEEKS) so the KPI label can adapt.
IkdQualityAggregator Habits tab (scatter) One DayQualityPoint per day with backspace + autocorrect counts Day index drives the alpha fade of older points.
IkdSensorTrendAggregator Trends tab (gyro / accel charts) Per-bucket avg gyro / accel magnitude Magnitude derived in Kotlin from AVG(x*x+y*y+z*z) — SQLite has no sqrt.
IkdSessionStatsLoader Per-session dashboard (KPI + chip row + metadata) SessionStats — counts, averages, durations One SQL round-trip; sentinels excluded via AVG(CASE WHEN col >= 0 …).
IkdSessionChartLoader Per-session dashboard (3 line charts) SessionChartData — IKD / gyro / accel series Bucket width auto-scaled; ≤ 200 points per chart regardless of session length.
IkdMoodLoader Per-session dashboard (mood KPI cell) Optional MoodEntry for the session Cell hidden when null.
LiveCaptureSessionStore Diagnostics dashboard In-memory event + sensor lists for the active session Push-based — no Room reads. Drains to Room every 500 ms or 100 events.

Performance budgets (from CLAUDE.md)

  • Global aggregator: Week < 100 ms · Month < 150 ms · All Time < 200 ms.
  • Per-session chart loader: 30 s session < 100 ms · 5 min < 200 ms · 1 hour < 400 ms.
  • Every loader logs its own wall-clock duration in debug builds (tags IkdAggregator, IkdMoodAggregator, IkdSessionStatsLoader, IkdSessionChartLoader).

Schema referenced

  • sessions — id, started_at, ended_at, counts, orientation, locale
  • ikd_events — session_id (FK CASCADE), timestamp, event_category, ikd_ms, hold_time_ms, flight_time_ms, is_correction, correction_weight
  • sensor_samples — session_id (FK CASCADE), timestamp, sensor_type (GYRO / ACCEL), x, y, z
  • mood_entries — id, session_id (FK CASCADE, unique), timestamp, mood_score (1..6)
Read-side only. Every aggregator listed here is additive over the existing capture rows. New dashboards or chart variants can be designed without reopening the keyboard / IME / capture layer.

Phase 9.11 — TODAY range + vertical tabs

Commits eb8454f2 (TODAY range), f00b5713 (tabs), be4d98ba (docs). Plan: roadmap/Phase9/sub_plans/9.11_today_filter_and_tabs.md.

Error-rate denominator fix (post-Phase-8.3)

Commit 569f331b. Manual test plan: roadmap/ErrorRateFix_TestPlan.md.

  • Two bugs in the Phase 7.1 weighted error-rate metric. (1) Denominator only excluded AUTOCORRECT rows, so typing hello world (11 chars) and backspacing all 11 read 11/22 = 50 % instead of the user-expected 100 %. Fixed by switching the denominator to productive keystrokes — eventCount - correctionCount — which excludes both AUTOCORRECT and BACKSPACE.
  • (2) BACKSPACE rows always carried correction_weight = 1, even when one keypress deleted an N-char selection or word-grapheme. Fixed by reading the selection length (or getCountToDelete()) before recording the timing event — new SimpleKeyboardIME.computeBackspaceWeight() helper.
  • Net: ocasdasda+autocorrect stays at 90 %; hello world<BS×11> now reads 100 %; legacy backfill drifts 18.18 % → 20 %.
