3. Hook-level call sites in SimpleKeyboardIME

The IME is where Fossify code calls into MoodScript code on the hot path of every keystroke. These are the architecturally load-bearing crossings.

onStartInputView SimpleKeyboardIME.kt:225–283
Keyboard opens. The IME calls maybeResetStaleMood(), builds a KinematicSensorHelper if absent, gates on !Config.privacyModeEnabled && !isPasswordField(), and on the happy path calls LiveCaptureSessionStore.startSession(orientation, locale) + sensorHelper.start(). Also resets the Phase-7 autocorrect trackers (expectedCursorPosition, lastImeEditTimestamp, …).
onFinishInputView SimpleKeyboardIME.kt:312–324
Keyboard closes. LiveCaptureSessionStore.stopSession() drains the in-memory buffer and finalizes the SessionRecord; sensorHelper.stop() unregisters listeners; best-effort writes Config.lastMoodActivityTimestamp when a standing rating exists.
onPress SimpleKeyboardIME.kt:345–360
Key-down event. Two-line MoodScript addition: when capturing, record SystemClock.uptimeMillis() into lastKeyDownTimestamp and compute pendingFlightTime from the prior lastKeyUpTimestamp. Original feedback path (performKeypressFeedback) untouched.
onKey SimpleKeyboardIME.kt:425–635
The heaviest crossing. Top of the method builds a KeyTimingEvent (sessionId / wall-clock timestamp / category / IKD / hold / flight / isCorrection / correctionWeight) and pushes it to LiveCaptureSessionStore.recordTimingEvent(). computeBackspaceWeight() reads the selection length (never the text) so a multi-char BACKSPACE contributes its full weight. Every Fossify commitText / deleteSurroundingText call site is now preceded by markImeEdit() — the Phase-7 grace-window signal for the autocorrect heuristic.
onText SimpleKeyboardIME.kt:714–717
Clipboard / popup-key text path. One added line: markImeEdit() before the commit so the resulting onUpdateSelection isn't mistaken for an external replacement.
onEmojiText SimpleKeyboardIME.kt:727–748
Phase 7 split out from onText via the new interface default method. Records an EMOJI KeyTimingEvent (hold = −1, flight from prior lastKeyUpTimestamp) before delegating back to onText(text). Lets the existing commit path remain unchanged.
onUpdateSelection SimpleKeyboardIME.kt:789–918
Phase 7 external-replacement heuristic. maybeRecordExternalReplacement(…) runs first; classifies any delta outside IME_EDIT_GRACE_MS of our last markImeEdit() as an AUTOCORRECT event using the select-range-then-collapse OR cursor-and-length-changed signatures. Field length is read via getExtractedText().length only — raw text never retained.
onSharedPreferenceChanged SimpleKeyboardIME.kt:1101–1123
Phase 13 reach-back: when LAST_MOOD_SCORE changes (mood-bar tap on Dispatchers.IO), call keyboardView?.notifyEmojiAdapterMoodChanged() so the open emoji drawer's curated section re-renders. Only place where the rebuild is guaranteed to see the committed value (race-condition note in plan).

7. Coupling assessment

Strong: interface-level extension (Phase 7)

OnKeyboardActionListener.onEmojiText() with a Kotlin default method that delegates to onText() is the cleanest crossing in the project. Every existing implementer of the listener keeps working; the IME overrides selectively to inject behaviour before delegating. Zero binary-compat risk, zero behavioural drift on the original commit path.

Strong: persistence isolation

MoodScript created a brand-new ikd.db Room database with its own RoomDatabase subclass, schema folder, DAOs, and migrations — never touching Fossify's clips.db. The two persistence surfaces share only the Context they're handed (safeStorageContext). A future upstream sync of clipboard code carries zero risk to MoodScript data.

Strong: DI via existing extension-property pattern

ContextExt.kt already exposed context.clipsDB. MoodScript extended the same pattern with 14 lazy Context.<helper> getters (ikdDB, ikdAggregator, ikdMoodBarController, …) — idiomatic Fossify-shaped, easy to mock at test boundaries.

Notable: capture writes are on the IME hot path but never block it

The original onKey() ran one commitText() per keystroke. MoodScript inserts a KeyTimingEvent allocation + LiveCaptureSessionStore.recordTimingEvent() call before it. The store only appends to in-memory lists under a write lock — actual DB persistence is deferred to the flushExecutor inside the store (write-behind, every 500 ms or 100 events). This honours the CLAUDE.md "Critical Constraint" of never blocking the IME thread on disk I/O.

Notable: Config is shared, not subclassed

MoodScript added 14 properties directly onto Fossify's helpers/Config.kt (which extends BaseConfig) rather than creating a separate IkdConfig. Pragmatic — the file gets a clear "Phase N" comment block per group — but it means upstream Fossify edits to this file are a likely merge-conflict surface. Mitigation: the additions are at the bottom of the file and use distinct pref keys, so conflicts should be mechanical.

Notable: SimpleKeyboardIME is the structural pivot

+480 lines on Fossify's 600-line IME service. The MoodScript additions are well-localised inside 8 callbacks and one preference listener, with private helpers grouped at the bottom (maybeRecordExternalReplacement, recordAutocorrectEvent, markImeEdit, computeBackspaceWeight, isPasswordField, maybeResetStaleMood). But because every commitText / deleteSurroundingText call site in the original code now needs a paired markImeEdit(), an upstream patch that adds a new commit call site would silently break the autocorrect heuristic.

Smell: About activity replaced wholesale

Fossify's org.fossify.commons.activities.AboutActivity is final and Compose-only with no public extension hooks, so Phase 10 replaced it with a local XML-based AboutActivity. The manifest was repointed and MainActivity.launchAbout() now startActivity(Intent(this, AboutActivity::class.java)) directly. Diverges from the Commons "About" contract (no LICENSE_GSON, no FAQItem list, no startAboutActivity helper) — benign for now, but future Commons "About" features won't reach this app for free.

Smell: VN Telex deliberately skips markImeEdit()

Inside onKey's VN Telex substitution branch, the comment explicitly notes "deliberately do NOT call markImeEdit() here" so the Telex setComposingText lands as an AUTOCORRECT event. This is semantically correct (Telex is an inline replacement) but couples the IKD heuristic to a specific Fossify code path. A future refactor of the Telex branch that consolidates with the regular commit path would change MoodScript's metrics silently.

9. Summary verdict

Architecture

MoodScript is a well-encapsulated extension on top of Fossify Keyboard. 79 added files vs. 13 modified bridge files (a ~6:1 ratio) means the bulk of the feature lives in isolated, MoodScript-owned modules. The 13 bridge files are touched sparingly with one architectural exception — SimpleKeyboardIME at +480 lines is structurally a MoodScript-shaped class now, even though it formally remains a Fossify service. The cleanest crossings are the interface-default-method pattern (onEmojiText) and the isolated Room database (ikd.db). The riskiest coupling lives inside SimpleKeyboardIME.onKey() where the paired markImeEdit() calls are an implicit contract no Fossify upstream contributor can see.
